# TPNAGL
Code of  “Tensorized Pure Nonlinear Anchor Graph Learning for Multi-View Clustering”

Repository
\- GitHub: [https://github.com/wangfii//TPNAGL](https://github.com/wangfii/TPNAGL).

Software Environment

**All required functions and dependencies are already included in this repository. After downloading the full project, the code can be used directly without additional installation.**

# Repository Structure
- ablation_study/      # Ablation experiment code
- datasets/            # Dataset used in the experiments
- funs/                # Functions required for the experiments
- maketu/              # Visualization scripts
- measure/             # Evaluation metric functions
- model/               # Experimental code (core model)
- res_test_opt1/       # Experimental results
- process.m            # Optimization code
- README.md

​	To reproduce the results in Tables 3–7, we first run the code corresponding to each dataset in the "`model/"` folder, for example, `run(MSRC_v1.m)`. All experimental results are then saved in the `res_test_opt1` folder. From these outputs, we select and record the performance values corresponding to the best parameter settings. For the baseline methods, we similarly execute their respective main scripts and record the performance under the optimal parameter settings. By collecting all these results, Tables 3–7 can be reproduced.

​	The results in Figure 2 can be obtained from the `res_test_opt1` folder by running `run("maketu/parameter_sen.m")`. For Figure 3, we first vary the value of parameter `k` in `MSRC_v1` and run the corresponding program. The generated results are saved in the `res_test_opt1` folder. After that, running `run("anchor_time.m")` produces the data required for Figure 3. The procedures for Figure 4 and 5 are similar. The corresponding results can be obtained by running `run("sigma_sen.m")` and `run("filter_t_sen.m")` in the `maketu` folder, respectively. For Figure 6, the visualization can be generated by running `run("model/MSRC_TSNE.m")`. For Figure 7, the code for plotting the objective function values should be enabled in the optimization script `process.m`, after which the figure can be generated by running the program.

##### Algorithm 

###### Evaluation pipeline: anchor learning → tensor fusion → SVD → *k*-means. 

![image-20260323152032712](https://github.com/wangfii/TPNAGL/blob/main/Image/Algorithm.png?raw=true)

The maximum number of iterations is set to Tₘₐₓ = 200, and the convergence threshold is ε = 1e-6. The stopping criterion is: $\|\mathcal{C}-\mathcal{J}\|_{\infty}\leq$ε or t >Tₘₐₓ

##### Reproducibility Statement

​	To facilitate reproducibility, we provide the full implementation of our method, along with dataset sources and detailed experimental settings. The experimental protocol, optimization process, and selected hyperparameters are described in the main text. In addition, the code repository includes scripts for training and ablation studies.

​	We also report the computational environment, including the hardware platform, to help readers estimate the resources required for reproduction. Sensitivity analysis and ablation experiments are included to demonstrate the stability of the proposed method and the contribution of each component.

​	Our current implementation does not enforce fixed random seeds. Therefore, slight performance variations may occur across repeated runs due to stochastic optimization, random initialization, and differences in hardware/software environments. Nevertheless, we provide the complete codebase and detailed settings to support reproduction of the overall experimental procedure and the main findings.

**Known Limitations for Reproducibility**

​	Although we provide the code, data access information, and detailed experimental settings, exact reproduction of the reported results may still be affected by several factors.

​	First, our implementation does not fix random seeds, and thus repeated runs may yield slightly different numerical results. Second, numerical outcomes may vary across different hardware platforms, which may lead to discrepancies from the results reported in the paper. Third, runtime measurements depend on the hardware environment and system load, and therefore may not exactly match those reported.

​	Despite these limitations, we believe that the released materials are sufficient to reproduce the main experimental results and to validate the conclusions of this work.
